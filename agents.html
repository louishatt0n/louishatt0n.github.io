The idea

Much of research is a loop: propose an idea, test it, keep what works, repeat. We built a system that runs that loop by itself. AI models write programs that attack a hard optimisation problem, a fixed judge scores every attempt, and the best ideas are kept, combined and improved over many rounds.

The problem we pointed it at

Simulating electrons on a quantum computer. To simulate a grid of interacting electrons (the Fermi-Hubbard model, a standard benchmark for quantum simulation), each time step has to be compiled into gates on a grid of qubits. The two-qubit gates are the slow, error-prone part, so the goal was simple to state: as few two-qubit gates as possible per term of the model.

Agents searched on small grids, were checked on a larger hidden one, and were scored at the end on a still larger grid that no part of the search had ever seen.

How it works

  1. Fix the rules first. Before any search, the problem and its scoring are frozen, and the judge's code is fingerprinted. If the scoring changes mid-run, the run stops.
  2. Start from what's known. A literature step gathers standard published approaches as starting points.
  3. Search in parallel islands. Independent groups of agents each evolve their own line of programs: propose an edit, score it, keep it if it's better, and back up when a line stalls.
  4. Choose the AI model like a bandit. Different models do better at different moments. Picking which one to call is treated as a multi-armed bandit, like choosing between slot machines with unknown payouts: keep backing whichever model is producing the most improvement for its cost, while still trying the others.
  5. Tune the numbers separately. Numeric settings inside a promising program are tuned automatically, so the models spend their effort on ideas rather than constants.
  6. Cross-pollinate. Each round, the leading program is paired with rivals that beat it on particular cases, and an agent merges their strengths into new hybrids.
  7. Keep variety. Survivors are picked to be good in different ways, not only for the top score, so the search doesn't collapse onto one idea.
  8. Score once on unseen data. The finalists are scored a single time on the sealed test, then written up.

Keeping the agents honest

Point an optimiser at a score and it will look for ways to game the score instead of solving the problem. Three guards against that:

  • A judge the agents can't touch. The fingerprinted scoring code means any change, by an agent or by accident, halts the run.
  • An exact check of the physics. Every circuit is verified to really implement the model, using algebra rather than simulating the quantum state. Simulation grows exponentially with size; the algebraic check works at any grid size.
  • The same split as a backtest. Agents only see feedback on development cases, selection uses separate validation cases, and the final score comes from a sealed test read once. It's the problem from my Bitcoin strategy test again: a search that sees its own test set will fit noise.

We also built a neutral judge to compare our system with open-source rivals on unseen cases, reporting confidence intervals rather than single best scores.

What I built

I wrote 49 of the 68 commits, mainly on:

  • The live dashboard (React, TypeScript): each island's progress round by round, the family tree of every program, and the lessons the agents logged as they went.
  • The cloud orchestration (Python, Modal): each run gets a single-use coordinator; if it crashes, a fresh one takes over the run where it stopped, with up to 16 model calls in parallel.
  • The API, the benchmark harness and the automated tests (29 test files).

Result

The system's best circuits needed 50% fewer two-qubit gates per term than a published rival system on the same benchmark, and the project won the Auto-Research Track.
